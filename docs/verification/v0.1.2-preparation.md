# v0.1.2 release preparation

## Changes

- Accept an optional top-level `family_name` in the family YAML file.
- Use `family_name: Smith` to show **Smith Family Wishlist** in the app header
  and browser tab, with matching family-list navigation and headings.
- Preserve generic wording for omitted, null or blank values, and keep personal
  wishlist headings and stable member/event identities unchanged.
- Trim names, accept up to 80 characters, and wrap long names on narrow screens.
- Provide validated branding through the public, read-only `/api/config/`
  endpoint. Configuration read errors return a generic, non-caching 503 response;
  the interface falls back to generic wording without disrupting identity checks.

## Compatibility

No database migration is required. Existing YAML files need no changes, and the
installation example leaves the optional family name commented out. Images
through `0.1.1` reject the new field; upgrade before enabling it.

Branding is read when the browser loads configuration. Reload after changing
the family name. Member/occasion changes still require backend synchronization
at startup; replaced Docker bind-mounted files require container recreation.

## Pre-publication evidence

The implementation and focused fixes passed independent Luna reviews, including
the long-name mobile boundary and safe configuration-error handling. A fresh
controller run passed 140 backend tests, 92 frontend tests, desktop and phone
browser workflows, Django/migration/dependency checks, lint and frontend build.

This is pre-publication evidence, not a claim of successful remote release.
The PR, main-branch and release workflows must pass before publication is
reported complete. ARM image smoke in CI uses QEMU, not native ARM hardware.

# v0.1.1 release preparation

## Changes

- Keep the app shell and gift drafts mounted during routine identity rechecks,
  while blocking interactions and concealing stale purchase details.
- Center the gift form and refine desktop/mobile spacing and presentation.
- Remove visible prices without deleting legacy stored/API prices.
- Require only the gift name and use the exact label
  **Can be purchased multiple times**.
- Add repeatable `seed_demo` and explicitly confirmed `reset_demo --yes` commands.
  Reset deletes only marked demo gifts and their purchase marks, not ordinary
  gifts, configured identities, occasions or sessions.
- Refresh synthetic-data screenshots and document isolated demo workflows.

## Compatibility and upgrade

The additive `0002_wishlistitem_demo_key` migration runs at container startup.
Back up the database, family YAML and private environment file before upgrading.
Keep the Compose project, named volume and secret unchanged. Demo commands are
optional; an upgrade never seeds or resets gifts automatically.

Name selection remains a convenience, not authentication. Trusted-family LAN
use is unchanged; this release does not add internet-hosting hardening.

## Pre-publication verification

The accepted application revision `72f5730` passed 135 backend tests, 83 frontend
tests, both desktop/phone browser workflows, Django checks, migration consistency,
dependency checks, lint and the frontend build. Independent Luna task reviews,
a whole-branch review and a final scoped re-review cleared the implementation.
Actual isolated Compose seed/reset checks and native Linux amd64 container smoke
also passed; see [local-source command evidence](local-source-demo-commands.md).

This record describes pre-publication evidence, not a successful remote release.
PR checks and the real release workflow must pass before deployment. ARM image
execution in CI uses QEMU, not native ARM hardware.
